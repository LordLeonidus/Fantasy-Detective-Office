# Идеи — общее для концептов

С 2026-10-31 идеи разделены на два концепта:
- [CONCEPT_open_case.md](CONCEPT_open_case.md) — городская игра по мотивам «Глухаря»: поток людей, проверки, глухари против статистики. **Развиваем первым.**
- [CONCEPT_uchastkovy.md](CONCEPT_uchastkovy.md) — участковый маленького городка: атмосфера, общение, ностальгия. Отложен.

Здесь то, что общее для обоих. Другие сеттинги, на которые можно перенести игру, — в [SETTINGS.md](SETTINGS.md).

## Время и место

- **Современность**, около 2010–2015, как в «Глухаре». Ничего советского.
- **Вымышленная страна**, узнаётся как Восточная Европа вообще, а не Россия, чтобы было интересно европейскому и американскому покупателю. Пример, что это продаётся: This War of Mine (город Погорен), Disco Elysium (Ревашоль).
- **Оставить:** панельки рядом с довоенными домами, пластиковые окна, застеклённые балконы, тарелки антенн, ларьки, букмекерские, западная реклама на облезлых стенах, машины 2000-х.
- **Убрать:** кириллицу, советскую символику, фуражку с красным околышем, узнаваемо российские бренды.
- **Вывески** на латинице с размытыми диакритиками (č, ł, ő вперемешку).
- **Форма** современная тёмно-синяя с выдуманными шевронами, описывать в промпте явно.

## Стиль (поиск, не решено)

Отправная точка — мультсериал «Эй, Арнольд!» (Nickelodeon, конец 90-х): атмосфера лёгкой депрессивности, переданная картинкой.

Что важно в этом стиле (по референсам в [refs/](refs/)):
- фоны нарисованы мягкой гуашью **без контуров**, с размытыми краями; обводка только у персонажей;
- простые формы, мало деталей (дома почти блоки с окнами);
- сумерки и ночь: густой сине-фиолетовый, тёплые жёлтые окна, одинокий фонарь, пустые улицы.

Риск: персонажи Арнольда комедийные и детские. Не брать: огромные головы, крупные глаза, яркий цвет, мимику на максимум. Не годится и гротеск (Ковалёв, Шоме): слишком уродливо.

**Стиль задают персонажи, а не кабинет** (решено 2026-11-01): кабинет будет перерисован под стиль персонажей.

**Стиль персонажей утверждён на этом этапе** (2026-11-01): лист `concepts/25_style_b_warm_v2.png` и сидящие посетители `concepts/26_visitor_irena_v2.png`, `26_visitor_tomas_v2.png`, `26_visitor_milan.png`. Чистовая фаза классической рисованной анимации: экономные уверенные линии, волосы цельными формами, на лицах почти только глаза, брови, нос и рот, плоские заливки с одной тенью, тёплая приглушённая кожа, матово, без глянца. Лица характерные, не красивые. Поза Томаша (не смотрит на игрока, показная) — поправить, когда дойдём до анимаций.

Ранние пробы, к которым ещё может понадобиться вернуться, лежат в `concepts/_temp/`.

Выводы для следующих проб:
- лист персонажей как референс держит единый вид жителей в карточках и сценах (на этом погорела Police Officer);
- «умеренный шаг стиля» от готовой картинки даёт фильтр поверх неё; если нужен другой стиль, просить полную перерисовку;
- готовая картинка на входе держит фигуры слишком сильно; чтобы перерисовать и тела, состав и одежду передавать текстом, а на вход давать только образец стиля;
- каждому персонажу прописывать своё строение лица и свою эмоцию, иначе все получаются одинаковыми;
- образец стиля вырезать из кадра, чтобы модель не тащила обстановку;
- нейросеть рисует лишние мелочи (мелкие морщины, отдельные волоски, складки, фактуру), которых человек-аниматор бы не нарисовал; чистить вторым проходом правки с явным лимитом линий на лицах — один общий проход по листу чистит одежду, а маленькие лица почти не трогает;
- для сцен скриншоты-референсы нужны крупнее (сейчас около 400 пикселей): нормальные кадры 16:9 из видео.

## Генерация картинок

Через Codex CLI из плагина VS Code. Исполняемый файл: `~/.vscode/extensions/openai.chatgpt-<версия>-win32-x64/bin/windows-x86_64/codex.exe`.

Рабочий запуск из Git Bash: промпт в файле, подаётся через stdin, Codex сам сохраняет картинку в `concepts/`:

```
codex.exe exec --skip-git-repo-check -s workspace-write -C "H:/GamesCreation/OpenCase" -i референс1.png -i референс2.png -o ответ.txt < промпт.txt
```

В промпте прямо написать: сгенерировать одну картинку и сохранить в `concepts/<имя>.png`, другие файлы не трогать. Так не нужно ни копировать из `~/.codex/generated_images`, ни бороться с кавычками PowerShell.

Вырезать кусок картинки: Python в системе нет, работает PowerShell через `System.Drawing`.

**Правка готовой картинки держит геометрию** (проверено 2026-10-31): если подать картинку первой и написать «это правка, ничего не двигать, поменять только свет», результат совпадает с исходником с точностью до 1 пикселя. Так из одной дневной базы сделаны все состояния кабинета `19_office_*.png`. Значит, состояния одной сцены по времени суток можно генерировать отдельно и плавно смешивать в движке.

**Огни окон отдельным слоем** (2026-11-01): кадры с огнями правкой перегенерированы в версии с тёмными окнами (`20_office_*_dark.png`), а скрипт `tools/art/extract_window_lights.ps1` из пары «с огнями / без огней» достаёт каждое окно отдельно. В утреннем тёмном кадре (`20_office_morning_dark_v2.png`) остались едва заметные тёплые крапинки: Codex не убрал их и со второй попытки; при необходимости обесцветить скриптом в области домов.
